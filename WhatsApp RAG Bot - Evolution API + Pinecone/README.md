# Tasks Orchestrator — WhatsApp AI Agent with RAG

> n8n workflow that turns WhatsApp into an intelligent task orchestration interface, powered by an AI agent with RAG (Retrieval-Augmented Generation) backed by Pinecone and Google Drive.

---

## Overview

This workflow connects WhatsApp (via Evolution API) to an AI agent that behaves as a **Tasks Orchestrator** — not just a chatbot. When a user sends a message, the agent interprets their intent, structures tasks into micro-sprints, selects the appropriate pipeline and skills, and responds with a structured execution plan. It also automatically indexes documents from Google Drive into a Pinecone vector store for knowledge retrieval.

## Features

### 1. Message Reception & Filtering
- Receives all WhatsApp messages via Evolution API webhook
- Immediately responds `200 OK` to avoid timeouts
- Filters out:
  - Messages sent by the bot itself (`fromMe: true`)
  - Group messages (`@g.us`)
  - Empty messages

### 2. Debounce Buffer
- Stores each incoming message in n8n's static workflow data, keyed by `remoteJid`
- Waits **4 seconds** before processing
- If new messages arrive during the wait, they are **consolidated** into a single input
- Prevents the agent from firing multiple times for rapid successive messages

### 3. AI Agent — Tasks Orchestrator
The agent operates under a strict system prompt that enforces structured task execution:

| Step | Description |
|------|-------------|
| Intent interpretation | Understands what the user wants to accomplish |
| Domain identification | Classifies the task domain |
| Complexity inference | Estimates effort and scope |
| Pipeline selection | Chooses the right execution pipeline |
| Skill selection | Picks relevant skills from the knowledge base |
| Sprint structuring | Breaks the task into micro-sprints |
| Acceptance criteria | Defines what "done" looks like |
| Validation | Confirms completion before moving on |

The agent adapts its behavior to the user model, including shorter sprints and clearer instructions for users with high cognitive load or ADHD signals.

### 4. RAG — Knowledge Retrieval
- Uses a **Pinecone** vector store (index: `tasks`) to retrieve relevant documents
- Embeddings generated by **Google Gemini** (`gemini-embedding-001`)
- The `company_documents_tool` is available to the agent whenever it needs to answer questions about internal policies, procedures, or products

### 5. Conversation Memory
- Per-user session memory using `remoteJid` as the session key
- Maintains context across multiple messages in the same conversation

### 6. Automatic Document Indexing
Two Google Drive triggers keep the knowledge base up to date:

| Trigger | Folder | Event |
|---------|--------|-------|
| `Google Drive File Created` | `Tasks-RAG` | New file added |
| `Google Drive File Updated` | `RH-Rag` | Existing file modified |

On trigger: file is downloaded → chunked (with 100-character overlap) → embedded with Gemini → inserted into Pinecone.

## Agent Response Format

The agent always responds as a task orchestration system, not a plain chatbot. Expected output structure:

```
[Task]
[type]
[complexity]
[pipeline]
[skills]
[current sprint]
[next action]
[validation]
```

For ambiguous inputs, the agent performs minimal refinement before structuring — avoiding unnecessary back-and-forth.

## How to Add New Documents to the Knowledge Base

1. Upload any file to the **Tasks-RAG** or **RH-Rag** Google Drive folder
2. The `Google Drive File Created` / `Google Drive File Updated` trigger fires automatically
3. The file is chunked, embedded, and inserted into Pinecone
4. The agent will have access to the new content on the next query

To add a new folder to watch, duplicate one of the Google Drive trigger nodes and point it to the new folder ID.

---

## Notes

- The debounce wait is set to **4 seconds** in the Wait node; the `DEBOUNCE_SECONDS` config key is a reference value and does not control the Wait node directly — update both if you change the delay
- The workflow only processes **direct (1:1) messages**; group messages are intentionally ignored
- The Pinecone index used for insertion (`Embeddings Google Gemini` → `models/gemini-embedding-2`) differs from the retrieval embedding model (`models/gemini-embedding-001`) — ensure both models produce compatible vector dimensions before changing either
- OpenRouter is using the free `minimax/minimax-m2.5` model; swap to a higher-tier model in the **OpenRouter Chat Model** node for production use
